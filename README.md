# India GDP Pulse

A dashboard of high-frequency indicators behind India's GDP, plus a transparent
GDP growth nowcast with its own confidence interval — built for The India Prosperity
Initiative.

All data is real, sourced from MoSPI's eSankhyiki portal, the RBI's Database on Indian
Economy, and the Labour Bureau. Nothing on this site is synthetic or placeholder data.

## How it fits together

This is the frontend half of a two-repo system:

- **[india-gdp-nowcast](https://github.com/AbhishekVS-TIPI/india-gdp-nowcast)** — the
  pipeline repo. It ingests source files, splices base-year series, applies manual
  corrections, fits the nowcast model, and exports `indicators.json`, `nowcast.json`,
  and one JSON file per indicator series.
- **This repo** — a static-data TanStack Start app. It reads those exported JSON files
  from `src/data/` at build time; there's no live API call at runtime. A weekly GitHub
  Actions job in the pipeline repo re-exports fresh data and pushes it here automatically.

See `src/routes/methodology.tsx` for the full writeup of sourcing, splicing, and how the
nowcast model works.

`nowcast.json` follows the contract in the pipeline repo (`docs/frontend_contract.md`): every
field the site needs is always there, and the Phase 0 fields (stress range, headline, members,
evaluation, coverage, live record) are optional, so the site works with an older export too.
Questions raised for the pipeline side, and how they were answered, are in `docs/pipeline-questions.md`.

## Development

Requires Node.js ≥20.19 (see `.nvmrc`) and [Bun](https://bun.sh).

```sh
bun install
bun run dev          # http://localhost:3000
```

| Script              | What it does                                                 |
| ------------------- | ------------------------------------------------------------ |
| `bun run dev`       | Vite dev server                                              |
| `bun run build`     | Production build to `.output/` (Cloudflare Worker via Nitro) |
| `bun run preview`   | Preview the production build                                 |
| `bun run typecheck` | `tsc --noEmit`                                               |
| `bun run lint`      | ESLint (includes Prettier)                                   |
| `bun run format`    | Prettier write (skips `src/data/`)                           |

CI (`.github/workflows/ci.yml`) runs lint, typecheck and build on every PR and push to `main`.

## Project layout

```
src/
  routes/       / (the briefing), /trends (the evidence), /indicators, /indicator/$id, /methodology
  components/   shared UI (SiteHeader, Card, charts); briefing/ and evidence/ hold each page's sections
  lib/          series.ts (data loading, y/y, release calendar), nowcast.ts (model output types and helpers),
                density.ts (odds from the exported density), evaluation.ts (the backtest against AR(1)),
                coverage.ts (what the headline reads), signals.ts (readings vs normal, breadth),
                sectors.ts (indicator -> sector map, model section crosswalk), attribution.ts
  data/         JSON exported by the pipeline repo (do not edit by hand)
  server.ts     Worker entry with an SSR error fallback
  start.ts      TanStack Start middleware (errors, CSRF)
public/         favicon, logo, robots.txt; index.html and pulse/ are the landing page (below)
scripts/        build-pulse-data.mjs writes public/pulse/data.js from src/data before every build
```

### The landing page

`/` is the recommended landing page of the Landing Demos moodboard, served as a static file: `public/index.html` plus `public/pulse/`
(`kit.js` charts and scenes, `story.js` the rules that write every sentence that quotes a number, `gdp.css`, `page.js` the chapters).
Cloudflare serves a matching static file before the Worker, so the React route in `src/routes/index.tsx` is only what `vite dev` shows;
links to `/` use `reloadDocument` so the browser asks the server for the real page.

`scripts/build-pulse-data.mjs` turns `src/data/nowcast.json`, `indicators.json` and `series/` into `public/pulse/data.js` (`window.GDP_DATA`);
`bun run build` and `bun run dev` run it first, so a weekly data refresh rewrites the page with no other change. `data.js` is generated and
git-ignored. To try the page on another export, `PULSE_NOWCAST=path/to/nowcast.json PULSE_OUT=dir bun scripts/build-pulse-data.mjs`.

The Stat team's note (chapter 7) appears only when `src/data/stat-note.json` exists (`date`, `quarter`, `title`, `teaser[]`, `more[]`, `watch[]`);
without it the chapter, and the "since this note" cards, are left out. "Your call" shows only in the week before a release.
With no evaluated range (more than about 45 days from a release) the page says so and calls the estimate too early to call.

`src/routeTree.gen.ts` is generated by the router plugin; never edit it.

## Build & deploy

```sh
bun run build
bunx wrangler deploy
```

The build uses Nitro's `cloudflare-module` preset and deploys as a Cloudflare Worker
(`wrangler.jsonc`).
